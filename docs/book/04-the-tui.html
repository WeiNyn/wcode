The TUI

A full-screen client over the same event stream: a pinned header, a transcript with a reading measure, a composer with a foot line, and — only when a team is working — a thin strip of members above the box. This chapter is the map, the keys, and the rules that keep it legible.

4.1The base: three bands, no more

The visual spec fixes the skeleton, and every later redesign amends it rather than inventing a fourth band:

Three rules do most of the visual work, all from the spec:

  • Role lives in the left gutter. One margin column, a marker column, content at a fixed column; wrapped lines align under the content, not the marker.
  • Dim is the workhorse. Under the default palette the screen is a grey ramp and red is the only hue — used for errors and failed tools. A preset (nord, gruvbox-dark, …) is an opt-in escape hatch.
  • Blank lines separate roles, not boxes. Tools are flat rows at the gutter column; there is no tree drawing (D023), no band rules, no double frame.

4.3Keys

The keymap is a single Rust constant — the same data renders F1 and /help, so the documentation cannot drift from the behaviour.

The three "modes" inside the TUI

Normal — typing goes to the focused surface. Browse (Ctrl-G) — a cursor over the transcript; j/k, g/G, {/}, / search, Enter to expand a block, y to copy. Overlay — a picker or info modal owns the keys until Esc.

Ctrl-C is two keys in one

While a run is in flight it cancels the run and stays. When idle it quits. In browse mode it still quits when idle — browse is a view, not a shield.

4.4Surfaces: a team in one window

With a team, each member is a surface. The root is wcode; workers are named. Input and /-commands go to the focused surface, so you can interrupt a worker mid-turn with a question without addressing it through the root.

  • Ctrl-N / Shift-Tab — cycle surfaces.
  • Alt-1..9 — jump to sidebar row N.
  • /surface — open the picker.
  • Ctrl-O — All vs Focus: All merges every surface's turns into one ordered transcript (default is Focus).

Because the merge is client-local, All mode is a view of data the client already has; it never asks the server for a combined history and never reorders the sessions themselves.

4.5Sidebar, strip, and overlays

Sidebar

Left-docked, 30 columns, shown only when the terminal is at least 80 wide (Ctrl-B toggles). Three sections: Team, Todos, Changes. The focused row is marked *.

Working band

A 0–3 row strip above the composer, one dim row per member while it runs — so a background worker is visible without stealing the transcript.

Overlays

Pickers (/model, /theme, /team, /surface, /resume) and scrollable info modals (/help, /verify, /usage, /tasks). ↑/↓ scroll a line, PgUp/PgDn a page, Esc closes.

4.6Colour, themes, and NO_COLOR

Seventeen roles live in crates/wcode-tui/src/theme.rs and nowhere else. A capability ladder picks the colour tier — plain, named 16, 256, truecolor — so a hex value is honoured only where the terminal supports it.

PresetCharacter
defaultNamed-16, bare grey ramp, red the only hue (D023). Safe on any terminal.
dark · lightTruecolor; light assumes a light terminal background.
gruvbox-dark · nord · solarized-dark · solarized-lightTruecolor escapes hatches; each overrides every chromatic role.
omarchyReads the live desktop theme from ~/.local/state/omarchy/current/theme/colors.toml; re-read on /theme omarchy.

Select with --theme <name>, [theme] name = "…", or a live /theme; --list-themes prints the catalog. Individual roles can be overridden in [theme] and survive a preset switch. NO_COLOR wins over everything and yields Theme::plain.

Why the default has no colour

Preference, not laziness. A grey ramp with one red reads at 7:1 contrast in any terminal and any light/dark setting; a colourful palette looks great in the author's screenshot and badly on someone else's solarized terminal. Colour is one flag away, deliberately.

4.7Commands from inside the TUI

Anything that maps to a Request works here: /model, /effort, /compact, /usage, /copy, /btw, /plan, /verify, /tasks, /team, /surface, /theme, /help, /exit.

Four commands are client-side re-execs and therefore refused over a socket: /resume, /new (alias /clear), and /reload [--no-session]. /changes lists the files this run changed and re-shows their diffs.

The session-lifecycle commands that are not requests (/sessions, /skills, /skill) stay in the REPL.
