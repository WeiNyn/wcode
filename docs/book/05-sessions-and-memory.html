Sessions & memory

A session is a file. That is the whole persistence design: append-only JSONL, one line per event, resumed by replay. On top of it sit two things that make long runs survivable — compaction, and the exact command that brings the conversation back.

5.1A file, not a database

Every session is a JSONL transcript under ~/.local/share/wcode/sessions — the same path on macOS and Linux, on purpose. Each line is one tagged entry; the file is appended as the conversation happens, so a crash loses at most the line in flight.

EntryWhy it exists
HeaderVersion, id, the cwd the tools ran in, creation time. Stamped first, so a truncated file is still identifiable.
MessageThe conversation. parent_id is reserved for future fork/tree sessions; the kernel is linear today and always records None.
ModelChange / EffortChangeMid-session switches are recorded, so resuming restores the model you were actually using — not the one in config.toml.
CompactionA summary plus the ordinal of the first message it does not cover. The transcript is never rewritten; the boundary is a new line.
TodoThe todo tool's checklist, last write wins — so a plan survives --resume and /reload.
Unknown#[serde(other)]: a file written by a newer wcode still loads on an older one instead of failing.

Two properties follow from "append-only text": a torn final line is tolerated (it is skipped), and session_search can read the file directly to recover turns a compaction replaced with a summary.

5.2Groups: a team is a directory

With a team, one root session cannot describe the whole run — each worker has its own transcript. So a team session becomes a group directory:

The file names are deterministic on purpose. A normal session gets a {millis}_{uuid8} name; a group needs root.jsonl and members/<name>.jsonl so an address can be mapped back to a file.

Resume rebuilds the team

Resuming a group does not just reopen a transcript. It scans members/, opens each file (torn-tail tolerant), seeds each worker with its full history, and re-establishes the registry edges and phonebook names — a live spawn, minus the spawn.

A corrupt or missing member file is reported and skipped, never fatal: losing one worker's memory should not lose the whole run.

5.3Resuming, exactly

--resume takes an optional path; bare, it takes the newest session. Either way the history is replayed as context — the model sees the conversation, but no turn is re-executed.

You get backBecause
The conversationEvery Message entry, replayed in order.
The model you were usingThe last ModelChange — unless --model is passed, which wins.
The effort you were usingThe last EffortChange — unless --effort is passed, which wins.
The todo listThe last Todo entry; /verify renders it.
The teamFor a group dir: rebuilt from members/.
Plan mode offDeliberate: plan mode is a live toggle, never persisted.

The line you will actually use

On a clean interactive exit wcode prints a copy-pasteable command that brings the session back, program name and all:

Every argument is single-quoted with embedded quotes escaped, so a task containing quotes still round-trips — the repository has a test that asserts exactly that (repl.rs:1816). A remote (--socket) session prints nothing: the server owns it, and relaunching locally would be a lie.

Two different resume: lines

An interactive session prints resume: wcode --resume <path> --model … --agents. A headless workflow run prints resume: wcode --agents --config … --timeout N --resume <group> --task '…' — it must carry the task and the cap, or the continuation would not be the same run. See Chapter 13.

5.4Compaction: the context you keep

Long sessions outgrow the window. wcode summarizes the older prefix rather than truncating it, and it does so under a policy you can tune — or ignore.

KeyDefaultMeaning
windowmodel's advertised windowOverride for models the catalog does not know; else DEFAULT_CONTEXT_WINDOW = 128_000.
budgetthe windowWorking ceiling. ceiling = min(budget, window) — a budget can never exceed the real window.
min_remaining16_384Trigger: used ≥ ceiling − min_remaining.
keep_recent_tokens20_000Recent context kept verbatim after a compaction.
keep_recent_turns2Whole turns kept regardless of size — so "what did we just say" is never summarized away.

Compaction is announced, not silent: AgentEvent::Compaction reports how many messages were summarized and how many were kept, and a best-effort attempt that could not run emits CompactionSkipped with the reason. /compact [focus] runs one on demand, optionally steering the summary.

Compaction does not destroy the transcript

The file keeps every message; a Compaction line is added. So the summary governs the live context, while the record remains complete — which is why session_search can still find a turn that the summary replaced.

5.5Looking backwards: session_search

The one memory tool. It reads transcripts, never the live context, and it is read-only.

ScopeBehaviour
all (default)Every session in the store, grouped by session; the current one is excluded unless include_current.
currentThis session's file — including turns a compaction replaced with a summary. Also takes turns{start,end} (a verbatim ordinal range) and stats (turn count + token estimate).

Terms are ANDed and case-insensitive; thinking and tool-result text is skipped unless include_tools. This is how an agent answers "how did we fix this last week?" without a vector database.

5.6What the session costs

/usage (or the Usage request) answers in one payload: turns, summed input/output tokens, the cache hit rate, per-tool calls / errors / result bytes, and a ~$ figure when the model is priced. With a team it prints one line per local member plus a total.

The pricing is deliberately honest: an unpriced model shows tokens and no cost, rather than a fabricated number. The session also exposes the same data to a client through Request::Usage, so the TUI's modal and the REPL's report cannot disagree.
