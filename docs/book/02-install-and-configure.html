Install & configure

One binary, one TOML file, one provider. This chapter gets you from nothing to a working turn — and explains the four ways configuration can arrive, because that is where most first-run confusion lives.

2.2Where configuration lives

Two directories matter, both under your home:

~/.config/wcode/ holds config.toml (provider, behaviour flags), agents/ (the conventional home for global role files — declared in config.toml as [[team]] file = "/abs/path/role.md") and wcode.sock when serving. Sessions go somewhere else — ~/.local/share/wcode/sessions (repl.rs:278), deliberately using ~/.local/share even on macOS so the layout is identical everywhere.

Four layers, later wins

  1. The global config ~/.config/wcode/config.toml The default provider and behaviour. A missing global file is simply "absent" — not an error.
  2. Project overlays, auto-discovered ./.wcode/config.toml, then ./.wcode/team.toml Folded over the global config, team second. Every team member is a [[team]] entry — inline, or file = "…md" — never a file the directory happens to hold. Disable the two overlays with --no-project-config.
  3. A named project team --team <name> → ./.wcode/teams/<name>.toml Replaces the project team.toml wholesale — a [[team]] array is never merged — so its roster is the session's team. Mutually exclusive with --config.
  4. An explicit overlay --config <path> / WCODE_CONFIG Deep-merged last. A missing or unparseable explicit overlay is a hard error — unlike a missing global file.

That "tables recurse, scalars replace" rule is what makes overlays usable: a repo can add [tools] grep = true without restating the rest of [tools], and a team file can replace the whole [[team]] array without merging members.

2.3A minimal, working config

Only model is required. Everything else has a sane default.

Provider precedence, in one rule

The globals (model/base_url/api_key/endpoint), the WCODE_* environment variables, and the --base-url/--endpoint flags together define the default provider. A [models.<id>] entry for the currently selected model overrides the fields it names — nothing more:

A model switch is therefore reversible: switching back to an unmapped id restores the default provider, with no state left behind.

FieldValuesDefault
modelany id your endpoint servesrequired
base_urlhttps://…/v1api.openai.com (warned, not silent)
api_keysecretOPENAI_API_KEY, or a placeholder for localhost
endpointchat · responses · autoauto — derived from the model id
effortfree-style, e.g. highunset — nothing is sent
Effort is free-style

Model listing returns ids, not capability flags, so wcode cannot know whether a model supports reasoning effort. It sends what you set and nothing otherwise — per endpoint: Chat sends reasoning_effort, Responses sends reasoning: { effort }, unset sends neither.

2.7First-run pitfalls

"It went to OpenAI and I didn't mean that"

base_url was unset. wcode warns on stderr at startup rather than silently defaulting — provider: … plus a warning line. Check with --dump-config.

"--model didn't fix my broken config"

Correct. Flags override a successfully loaded config; an unreadable or invalid config.toml still exits with an error. --model rescues a missing model, not a broken file.

"grep and find don't exist"

They are off by default ([tools] grep = true, find = true). The model can always search with bash; the dedicated tools are opt-in because a smaller tool set is a cheaper prompt.

"My project settings are being ignored"

Project auto-discovery starts at the working directory and walks up to the repo root looking for .wcode/. Run from a subdirectory and it still works; run from outside the repo and it cannot. WCODE_PROJECT_CONFIG=off disables it deliberately.
