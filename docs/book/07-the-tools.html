Part III · Inside · Chapter 07

The tools

Eighteen tools: thirteen every session gets, two that depend on a flag or a binary, and five that only a root ever sees. This chapter is the reference — what each tool promises, what it refuses, and the three policies wrapped around them.

7.1What registers, and when

The tool set is a Rust function, not a config list. Two tools are conditional on your [tools] flags (because bash can do their job), two are conditional on a binary being present, and one family is root-only.

7.2Reading and searching

read the numbering is for locating, not addressing

Prints <line number>\t<content>. The number feeds an offset or a citation; it is never an address. A line longer than 300 characters is truncated with …(+N) — and a truncated line is not usable as an old_string, which is why the tool says so.

grep off by default

Regex search returning path:lineno:content, so a hit pastes straight into an edit as old_string and into a read as offset. It respects .gitignore (plus a built-in floor of .git, target, node_modules) and skips binaries; no_ignore: true searches ignored files too.

find off by default

Glob listing, one path per line. Same ignore semantics as grep.

ast_search needs ast-grep

Structural search with $UPPERCASE wildcards — "find every call whose second argument is a string literal", which no regex can express reliably. Registered only when the binary exists, so the model never holds an unusable tool.

Why grep/find ship off

A tool set is prompt budget. If the model can search with bash, a dedicated tool must earn its schema bytes. Repositories that want them (this one does — see .wcode/workflow.toml's [tools] grep/find = true) turn them on in one line.

7.3The shell, and the three policies around it

bash is sh -c in the working directory: stdout, labeled [stderr], exit code. 30 s default timeout, Ctrl-C kills the process group. Three separate mechanisms shape it.

1 · The catastrophic-risk gate (always on)

No config knob, no allowlist — a fixed set of commands that would destroy the machine is refused before execution, and the model receives a blocked: error explaining why.

The carve-outs are deliberate: dd if=/dev/sda of=/tmp/img (reading a device into a file) is allowed; only of=/dev/… and a redirect into a device are refused.

2 · Plan mode (opt-in, toggleable)

While plan mode is on, mutating shell commands are refused by a denylist — see Chapter 10.

3 · The token filter (opt-in, rtk)

If rtk is on PATH (the default is auto), every bash call is first passed through rtk rewrite. A rewrite means the command runs as rtk … and the model sees compressed output; no rewrite, or any failure, means the original command runs untouched.

7.4Long commands: bg

Any bash call can be started in the background (bash { background: true }), and bg manages it: list, status <id>, output <id> [tail], wait <id> [secs], kill <id>.

The part that matters: a finished task pushes a [message from bg] back into the session — a turn if the session is idle, next-turn context if it is running. So a five-minute build does not require the model to poll, and a polling loop (which would block the message it is waiting for) never has to exist.

wait defaults to 60 s and caps at 300 s; the spill file path is printed with the tail so long output is recoverable.

7.5Writing safely

edit, edits and write share one mutation lock and write through a temp file plus an atomic rename. Two consequences: concurrent file mutation cannot interleave, and a crash mid-write cannot truncate the target.

The editing contract itself — byte-exact matching, the two error codes, batch atomicity — is Chapter 08's subject.

7.6The web

webfetch GETs a URL over http(s) and reduces HTML to readable text. format selects text/markdown/html (default markdown); the body is capped at 5 MiB and the output at 40k characters, so one page cannot flood the context. It is read-only and always registered.

GET only, by construction: no method, headers, body, or cookie parameter exists. If a page needs a session, it is not fetchable — which keeps the tool's blast radius at "read public text".

7.7Session-local state

todo — the checklist

Call with todos to replace the whole list (each item content + status pending/in-progress/completed), or with no args to read it back. Registered in every session, workers included. Persisted as a Todo session entry, so /verify works after a resume.

session_search — the archive

Reads transcripts, not context. scope: all scans the store; scope: current reads this session and can return a verbatim turn range or a token estimate. Fully described in Chapter 05.

Five tools exist only for a root orchestrator (a worker's tool set has none of them, so only the root plans or delegates):

7.9What is not a tool

No MCP client, no plugin loader, no dynamic registration. A tool is a Rust type compiled into the binary: typed args (schemars schema), a description, an execute. That is why the tool set can be reasoned about — and why adding one is a ten-line diff rather than a protocol negotiation.

To write one, see Chapter 17.
