Part IV · Teams & pipelines · Chapter 13

Workflow mode

Declare the plan in TOML, hand it a task, and walk away. The scheduler dispatches each ready node to its member; the root relays verdicts; the process exits with a code that means something. This is Chapter 12's DAG with the plan written in advance.

13.1The fence: --task

A [workflow] table is a template. It instantiates only when a task arrives — otherwise it is inert and wcode prints one line and boots normally.

All three conjuncts earn their place:

  • has_task — a headless pipeline with no task has nothing to do, and an interactive one would fight the root's own planning. Without it: the notice "workflow: present but inert (no --task)" (main.rs:1381).
  • !resuming_group — a resume loads the journaled plan; re-seeding would grow it by N nodes on every resume.
  • has_workflow — nothing to instantiate otherwise.
FlagRequires / refuses
--task <text>Requires [workflow] and --agents; refuses -p and serve. WCODE_TASK is the env fallback.
--timeout <secs>Requires --task. 0 = no cap, overriding [workflow] timeout_secs.
--quietSuppresses the per-event log; the summary and any resume: line still print.
--status [group|latest]Read-only plan dump. Refused when a task is set (including via env).

The judge edge

A judge is a one-shot, zero-tool completion: it sees the criterion and the upstream node's artifact, and must answer with one verdict line.

An unparseable reply is not a skip — it blocks and escalates. Only a real VERDICT: SKIP prunes the branch, so a confused judge costs a human's attention rather than silently deleting a step.

13.3Boot: three gates, then a plan

  1. Structure config.rs:1057 validate_workflow_structure Unique ids, one edge per pair, no self-edge, known endpoints, gate needs a dep, condition is exactly one kind, scripts non-empty.
  2. Acyclicity config.rs:1175 topo_order Produces creation order — which is why an edge may legally name a node authored later in the file.
  3. Members config.rs:1155 validate_workflow_members Every member must resolve in the declared team (a [[team]] entry, file = members resolved first), so a typo cannot create an undispatchable node.
  4. Instantiate main.rs:2951 create (title + deps + gate) → assign (agent:<member>) → configure (RunSpec + per-node deadline). Journals as it goes.
  5. Spawn the scheduler main.rs:1668 After the plan exists and the team is owned — never before, or a resumed Doing node would never be re-dispatched.

13.4The seed: one fence, not a briefing

The root's opening instruction assumes the plan already exists. Its job is verdicts, not planning.

"Do not message its member directly" is not a prohibition on teamwork — it is a prohibition on solving a node out of band, which would leave the plan describing something that never happened.

13.7Exit codes, observability, resume

ExitMeaning
0Every node Done or Skipped.
1A node Failed (fail-fast), the run cap elapsed, or the root's first turn errored / hit max turns.
2No plan loaded — refused before the root is seeded, so no run.json and no false resume:.
130Ctrl-C: cancel the run, print the resume line, exit immediately.

The verdict is a pure function of the plan, not of the model's closing paragraph. A run narrates itself on stderr (#id [state] title transitions plus root reports); the final per-node summary goes to stdout and always prints.

--status reads through TaskList::read_at and deliberately not load_at — the latter journals a Restart into the very file being inspected. A resume reloads the journal (Doing → Todo), rebuilds the team from the group directory, and does not re-seed.

The brainstorm step is deliberately absent

The shipped pipeline has no "write the brief" node. A brief needs a human's sign-off, and a headless run has none — so that step lives in the prompt layer ([orchestrator] guidelines in .wcode/team.toml) and in a skill, not in the graph. Putting it in the graph would produce a pipeline that signs off on its own work.
