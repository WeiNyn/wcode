Instructions & skills

Two mechanisms for telling the agent how your repository works — and they are deliberately different. Instructions are always in the prompt. Skills are a catalogue in the prompt whose bodies load only when needed.

9.1Instruction files: a discovered set, not a list

wcode does not read one "rules file". It discovers a set: one global file in the config directory, plus one candidate per directory walking from the repository root down to your working directory. Nearest last — so the most local file has the final word.

OrderSourceNote
1~/.config/wcode/<name>The global file — first in the block, so a project file overrides it in spirit.
2 … Nrepo root → working dirOne candidate per directory, nearest last. Run from a subdirectory and both levels load.

Two budgets, and what happens at them

32 KiB per file · MAX_FILE_BYTES = 32_768

A single file beyond this is truncated. A 200 KB AGENTS.md would otherwise crowd out the actual task.

64 KiB total · MAX_TOTAL_BYTES = 65_536

Files that would exceed the combined cap are dropped from the least specific end — the global file first — so the nearest project file always survives.

Controls

WantDo

Load exactly one file, no discovery[instructions] file = "AGENTS.md" (a name walked up, a relative path, or absolute)
Different candidate names[instructions] names = ["CONTRIBUTING.md"]
Skip the global file[instructions] global = false
See exactly what the model gotwcode --dump-system-prompt
Why a set, and why nearest-last

A monorepo needs repository-wide conventions and a package's own deviations. Loading one file forces you to choose; loading the chain lets the nearest file speak last, which is the same precedence a reader would expect from nested configuration — without any merge logic.

9.2Skills: progressive disclosure

A skill is a directory with a SKILL.md: YAML frontmatter (name, description) plus a body. Only the name and the description enter the system prompt, as an # Available skills section. The body loads when the agent reads the file.

The economics are the point: twenty skills cost twenty one-line entries, not twenty bodies. A body is loaded only when a task actually matches — so the catalogue can be large and the per-turn cost stays flat.

Discovery order (first name wins)

  1. Explicit roots [skills] dirs / WCODE_SKILLSScanned first, so a project can pin its own set.
  2. The working dir and its ancestors .wcode/skills, then the shared pairThe shared pair prefers .agents/skills and falls back to .claude/skills where .agents is absent.
  3. Global roots ~/.local/share/wcode/skills, then the shared pairSo a skill travels with you across repositories.

Limits that keep the catalogue honest

LimitValueWhy
Prompt descriptionMAX_PROMPT_DESCRIPTION_CHARS = 200One line per skill, enforced.
Whole sectionMAX_SECTION_BYTES = 16_384The catalogue itself cannot crowd out the task.
Scan depthMAX_SCAN_DEPTH = 4Bounded walk; a deep tree cannot make startup slow.
Name / description64 / 1024 charsFrontmatter validation; malformed skills warn and are skipped, never fatal.

When the model does not pick it up

Descriptions are chosen by the model, and models are imperfect. Two escapes:

/skills

List what was discovered — name, description, file — so you can see whether the skill is even visible.

/skill <name> [args]

Force the body into a turn. Extra args become the task. This is the "I know the tool exists, use it" override.

KnobEffect
--no-skills / WCODE_SKILLS=offNo discovery at all.
[skills] enabled = falseSame, from config.
[skills] dirs = ["./team-skills"]Extra roots, scanned first.
[skills] disabled = ["noisy"]Skip by name.

9.3Instructions vs. skills vs. role files

Three things that all look like "markdown the model reads", with three different lifetimes. Getting the wrong one is the most common setup mistake.

InstructionsSkillsRole files
FileAGENTS.md, CLAUDE.md, …SKILL.mda role .md, declared with [[team]] file =
Reaches the promptAlways, in full (up to the caps)Name + description onlyThe body becomes the worker's # Role
ScopeEvery session in the treeEvery session; body on demandOne team member
Right forConventions, commands, guardrailsProcedures, checklists, scriptsWho a worker is and how it reports
Chapterthis onethis one11
The rule of thumb

If it must be true in every turn, it is an instruction. If it is a procedure the agent should perform sometimes, it is a skill. If it describes who a teammate is, it is a role.
