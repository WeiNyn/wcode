Part VI · Reference & craft · Chapter 16

Troubleshooting

Symptom, cause, fix — and the command that proves which one you have. Almost every entry here can be diagnosed without spending a token.

16.1It cannot reach the model

SymptomCauseFix / proof
"no API key" error No api_key, no OPENAI_API_KEY, and a non-localhost base URL Set the key — or point at a local endpoint; the localhost forms build keyless. wcode --dump-config shows the key slot as (none).
401 / 403 Wrong or expired key wcode --list-models — it fails here too, with the provider's message.
404 on a valid model Endpoint mismatch: chat vs responses --endpoint chat (or responses) for one run; pin it in [models.<id>] if it is permanent.
Requests go to OpenAI and you did not mean that base_url unset Startup already warns on stderr. --dump-config shows the effective base URL and its source.
Empty model list The endpoint has no /models route (many local servers) Not fatal — pass --model explicitly. Model listing is convenience, not a requirement.
Long pauses, then "Retrying" 429/5xx or a connect stall Expected: bounded retries with backoff. Tighten or disable with [retry]. Reproduce deterministically against a refused port: --base-url http://127.0.0.1:9/v1 with WCODE_RETRY_MAX=2.

16.2The model cannot find its tools

SymptomCauseFix / proof
grep/find "unknown tool"Off by default[tools] grep = true / find = true, or WCODE_GREP=1.
ast_search missingNo ast-grep/sg on PATHInstall it; detection is automatic, and the tool is never registered unusably.
A planned tool call never runsA policy refused itLook for a blocked: … tool error in the transcript — plan mode, bash risk, or the verify gate. All three explain themselves.
Reads race writesYou disabled parallelism or expected itRead-only tools run concurrently; mutating ones are barriers. --sequential is the opposite knob.

16.3Edits are refused

ErrorWhat actually happenedFix
E_NO_MATCHThe literal text is not in the file — whitespace, indentation, or the file changedRe-read the region; copy the text. A read line truncated with …(+N) is not usable as old_string — use grep to get the exact bytes.
E_AMBIGUOUS_MATCHThe text occurs more than onceInclude another line to pin one occurrence — or replace_all if you truly mean all.
E_EMPTY_OLD_STRINGold_string was emptyGive the text; use write for a whole-file rewrite.
A whole edits batch refusedOne op failed; the batch is atomicThe error names the op (op2). Fix that op — nothing was written.
"plan mode: edit is disabled"Plan mode is on/plan off. It is never persisted, so a new session is already off.

There is no staleness error class, by design: a changed file simply stops matching, which is the same E_NO_MATCH. See Chapter 08.

16.4The plan will not advance

SymptomCauseFix / proof
"workflow: present but inert (no --task)" D001 — a [workflow] without a task does nothing Pass --task "…" (and --agents), or use [team] for interactive work.
task complete <id> blocked: "verify gate required" R′ — the node has no gate depending on it Create a gate with deps: [id], gate: true and assign it. In a template, add an edge plus a gate = true node.
The pipeline deadlocks at node #1 Same rule, in the template A bare work node is a deadlock, not a warning. Check with wcode --status latest after one refused-port boot.
"scheduler: N node(s) failed — the plan is stalled" Rework cap hit, or a node was failed outright task reset <id> to retry, or accept it and stop. The escalation names the node and the reason.
"node timeout: exceeded Ns" The per-node timeout_secs fired Raise it, or remove it (unset = unbounded). The dependents are blocked until a reset.
A node never runs though nothing is running No owner (a Session node with no assign) The frontier skips it silently by design. task list shows the missing owner.
--timeout ignored --timeout without --task is a boot error; 0 means no cap [workflow] timeout_secs is only the default when the flag is absent.

16.5Team trouble

SymptomCauseFix / proof
A role "stopped working" A [[team]] entry of the same name shadows the .md file wholesale Grep your config for the name. TOML wins over project .md, which wins over global.
error: team member `x`: unknown tool `foo`; valid tools: … The allow-list names a tool that is not registered (grep/find are off by default) Either enable the tool in [tools] or drop it from the list. Boot fails loudly on purpose.
Worker replies but the plan does not advance The root must call task complete — a report does not close a node Expected. In workflow mode the seed says so; in team mode the root decides.
The root hangs "waiting" It is polling — a sleep or a loop blocks the Wake it awaits It must end its turn instead. SleepRefusalHooks refuses a sleep-leading command at the root.
"NotPermitted" on a message No ownership edge and no allow_pair grant Members may talk to their owner; workflow edges grant lateral pairs. Otherwise it is a design error, not a bug.
A member was not resumed Its transcript is missing or corrupt Reported as a warning by design — one lost worker must not lose the run.

16.6Sessions, prompt, and presentation

SymptomCauseFix / proof
No resume: line at exit--no-session, or a --socket clientExpected: nothing to resume locally.
A workflow run has no run.jsonAlso --no-session (no group dir)Drop the flag if you want a resumable run.
--resume restores the wrong modelIt restores the last ModelChangePass --model — the flag wins.
Instructions not appliedWrong directory, wrong candidate name, or the budget dropped the filewcode --dump-system-prompt is the ground truth. The nearest file always survives the 64 KiB cap.
Skill not discoveredNo description, invalid YAML, or deeper than 4 levelsMalformed skills warn on stderr and are skipped. /skills lists what was found.
TUI did not startInput or output is not a TTY, or -p/serve/--taskForce it with --tui (it will need a real terminal), or use --no-tui deliberately.
Colours look wrong / noisyA truecolor preset on a 256-colour terminal, or the inverse--theme default (named-16) or NO_COLOR=1.
A long background command "vanished"It finished and pushed a message you did not readbg list, then bg output <id>; the spill file path is printed with the tail.

16.7The three commands that answer most questions

  1. wcode --dump-config no model, no session The resolved model, endpoint and base URL, and where each value came from. Keys render as (set)/(none) — the secret is never printed.
  2. wcode --dump-system-prompt no model The exact prompt: base text, instruction files, skill catalogue, team roster, orchestrator guidelines. If a rule is not in here, it is not in play.
  3. wcode --status latest no model, no socket, provably no write The plan as journaled. Use it after any headless run to see which nodes exist, their states, and (in the journal's create lines) their deps and gate flags.
Reproducing without a provider

A local OpenAI-compatible server (--base-url http://localhost:11434/v1) exercises the happy path; a refused port (http://127.0.0.1:9/v1) with a small WCODE_RETRY_MAX exercises the error path. Neither needs a key, and neither costs anything.
