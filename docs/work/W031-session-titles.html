Session titles

A session's only handle today is an opaque {millis}_{uuid8} key plus the first thing somebody typed. This item gives it a name: an append-only Title entry, generated once by the model after the second turn, and settable by hand when the guess is wrong.

1The ask

verbatim

rename session, session should support rename, and the rename using llm to rename session, the rename action auto trigger by the loop after n turns (default = 2), such that we can easily find session on resume (semantic name > default id + first message)

Three deliverables, in the requester's own priority order:

1 · Rename

An explicit capability. If the generated name is wrong, the user must be able to overrule it — in both clients and over a socket.

2 · Semantic

The name is produced by the model, from the conversation, so it describes the work rather than the first sentence of it.

3 · Automatic

The loop fires it after N turns — default 2, configurable, and switchable off. Nobody should have to remember to name a session.

The driver is the /resume picker. Its row is assembled by one function in the CLI, and the id leads it:

Two of those three parts are weak. The id is opaque by construction — it is {millis}_{uuid8}, which is deliberate, because the ordering of the session directory is chronological by filename and five separate parsers depend on that shape. And the third part, as the next section shows, is not merely weak: for the sessions that matter most, it is wrong.

2A bug found on the way

found while briefing · fixes a real defect

Every compacted session currently labels its picker row with the constant string Summary of the earlier conversation (auto-generated by compaction): — so the longest, most valuable sessions are the ones you cannot tell apart.

The cause is a collision between two reasonable decisions. Replay prepends a compaction summary as an ordinary user message, and the picker scans for the first user message:

Session::messages() prepends AgentMessage::summary(…) whenever a compaction boundary exists, and summary() is a User message (crates/wcode-harness/src/message.rs:73). So the first User in a compacted session is never the user's — it is the machine's.

The titler reads the same two messages, so both must walk persisted entries and skip the synthetic summary. This is worth shipping on its own merit, independently of titles.

3Scope

In

  • SessionEntry::Title — appended, last-write-wins, read by Session::title()
  • A bounded one-shot titler: first user message + first assistant text in, ≤ 60 chars out, sanitized
  • An automatic trigger at a turn boundary, gated on title_after_turns (default 2, 0 = off)
  • Agent::set_title, Request::SetTitle, AgentEvent::SessionTitle, plus the idle and deferred actor arms
  • /rename <text> in the REPL and the TUI
  • --title <text> at launch
  • [session] title_after_turns + WCODE_TITLE_AFTER_TURNS + a --dump-config line
  • The picker row prefers the title — and §2's bug fixed by the same helper
  • The title in the TUI header segment and the REPL's /sessions

Out

  • VS Code's picker. It reads only the first 32 KiB (sessions.ts:104 readHead(path, 32 * 1024)), so a tail-appended entry is invisible for any long transcript. That is a head-reader-vs-tail-entry problem, not a label tweak — its own work item
  • Renaming the file or group dir. Five parsers depend on the filename; the title is content
  • Re-titling on a schedule. Churn, drift, and it renames a session the user has learned to find
  • session_search reporting a title. A different reader; a good follow-up
  • The socket client's blank · session segment. A separate plumbing bug — the local path already sets it (main.rs:1963)
  • A live picker refresh. set_sessions is seeded once at boot; the row is stale until the next launch, and the status line confirms instead

Deferring VS Code has a stated cost: for a titled session the two pickers disagree — wcode shows the title, VS Code the first user line. Both rows identify the same session; nobody is misled, only less pleased.

5Decisions

5.1 The title lives in the session log, as an entry

The session is an append-only JSONL of tagged entries, and it ends in a catch-all. That catch-all is what makes this change safe for every copy of wcode already installed:

why this is the safe shape

One reader. Session::open remains the only thing that parses a session file. Torn writes are tolerated. It already breaks on a bad final line, and a Title line inherits that. Released binaries are unharmed. Deserialising a line they do not know hits #[serde(other)] Unknown and is a no-op. A meta.json sidecar would need a second reader, a second path convention for group directories, and a second torn-write story.

The precedent is Todo: an appended, last-write-wins entry read with self.entries.iter().rev().find_map(…). Compaction is the precedent for an entry whose payload is model-produced text. A title is the intersection of the two.

5.2 Derived from the first exchange, not the whole context

The first user message and the first assistant text, each clamped to ~600 characters — roughly 400 input tokens and 15 output, once per session. The whole context is rejected on three counts: a hundred-turn session makes naming it a full-context request; the tail describes the latest work rather than the session's purpose, so a title would drift; and the cost becomes unbounded and unpredictable for a background call.

The same two messages feed §2's bug fix. One helper, two callers.

5.3 The trigger — open question D1

Recon first claimed the loop is the only writer of a session file, which would have forced the loop to block. That was wrong, and the correction reshapes the design — a second writer already exists and documents its own safety:

So the constraint is not "the loop must write" — it is "one short O_APPEND write". Three ways to spend that:

(a) Block inline

Await the title call at the turn boundary, exactly like auto-compaction (loop_.rs:177). About fifteen lines, no plumbing, failure already has a precedent (CompactionSkipped).

Cost: one full request of dead time at turn 2 — the moment a user is most likely mid-typing. Mitigated by the input queue, so keystrokes are queued, not lost.

(b) Spawn and settle

Spawn the call, drain it with an is_finished check at the next boundary, and settle it with a bounded wait on every exit path.

Cost: a second in-flight future in the kernel, plus a settle wrapper around eleven return finish(…) sites. No stall.

(c) Client-side policy

The CLI already observes every turn end. Count to N there and send Request::SetTitle; the existing mid-run deferral (actor.rs:652) applies it at the run boundary.

Cost: needs its own request framing — side_ask_with hardcodes the /btw preamble. Kernel untouched: no settle wrapper, no new future.

orchestrator's read

(a) is the smallest correct change. (c) may be strictly better than both and deserves the reviewer's first pass before anyone writes an eleven-site settle wrapper. The brief as delivered recommends (b).

5.4 What counts as a "turn"

Assistant turns, counted from persisted state: title when the count satisfies title_after_turns and no Title entry exists. Both alternatives fail a common case —

CandidateFails because
The loop's own counter It resets at every run(), so a plain five-exchange chat with no tool calls never reaches 2.
User submits A one-shot -p run that does all its work in one submit runs many turns and would never title — the case most worth titling.
Assistant turns — covers both, needs no new counter, and being derived from persisted state it agrees across a resume. A compaction cannot inflate it, since the summary is a User message.

On --resume the existence check short-circuits before the count: no re-title, no counter restart. A session created before this feature titles itself at its first boundary — a deliberate, one-request backfill.

5.5 Overwrite policy

Set once. The loop never overwrites an existing Title. /rename appends a new entry, which by definition also disables the auto-titler for that session — the user has spoken. Re-titling on a schedule was rejected: one request and one line per N turns for the life of a session, semantic drift, and it silently renames a session somebody learned to find.

5.6 The explicit rename surface

/rename <text> on both human surfaces, plus --title <text> at launch — all travelling as Request::SetTitle. The flag must not be called --rename, and must not collide with --name, which already owns the A2A address (main.rs:196).

a socket bonus

/rename works over a socket, because it is a request the server applies. /resume is refused there for a good reason — it is a client-side directory listing the server knows nothing about. A rename is not.

5.7 Config shape

A per-knob Option<usize> on a new [session] table, absent meaning the kernel default — the same shape as [tui] view, including its loud validation. Range 0..=50; an out-of-range value fails at startup naming both the value and the range. WCODE_TITLE_AFTER_TURNS beats the file, as everywhere. One --dump-config line, so the gap that bit [compaction] budget is not repeated.

6The interface

Request::SetTitle is additive to a tagged enum, and the protocol's own rule is that additive changes do not bump PROTOCOL_VERSION — which is exactly the argument AgentEvent::CompactionSkipped already records for itself. The same event variant serves both as the reply to a request and as the notification when the automatic title lands; the envelope already supports both uses.

9How it gets proven

Unit tests alone are not evidence here — the whole feature is about what a user sees in a picker. Three live checks against a real binary, running on the endpoint and key the global config already resolves.

not a local model · this is the point of the check

The titler is an instruction-following probe: its contract is “3–6 words, no quotes, no trailing period, nothing else”. A small local model is the instrument most likely to miss that instruction — and it misses it in a way that looks identical to a bug in sanitize or in the trigger. A flaky check does not merely waste time; it teaches the next person to ignore the result. So the live run takes no --base-url and no --model, and inherits ~/.config/wcode/config.toml.

Two further consequences. It costs real tokens: two turns plus one small title request, once per session, never re-requested for a session that has a title. And it exercises sanitize for real — a competent model still emits quotes and trailing periods often enough that the sanitiser is genuinely tested, which is a benefit of the real endpoint, not a cost of it. Unit tests stay hermetic: they drive a scripted StreamFn and never touch the network.

the no-stall claim is unproven

That the title costs no user-visible pause is an argument from design, not a measurement. It is proven by comparing the gap between turn 2's end and turn 3's start against a build with WCODE_TITLE_AFTER_TURNS=0. Until that comparison exists, the claim is a hypothesis.

10Expected outcome

  • A session's transcript tail can carry {"type":"title","id":…,"title":"…"} — appended, never rewritten, invisible to every released binary.
  • /resume rows lead with the semantic title; untitled sessions keep exactly today's row; and a compacted session stops labelling itself with the compaction banner.
  • The title appears after the second assistant turn with no user-visible pause; WCODE_TITLE_AFTER_TURNS=0 removes the request entirely.
  • /rename works in the line REPL, in the TUI, and over a socket. The TUI header and the REPL listing update immediately.
  • --title sets the name at launch, fresh or resumed, and suppresses the guess.
  • --dump-config prints the resolved value; a bad one fails at startup naming the value and the range.
  • The two pickers disagree for a titled session — recorded, not a surprise.

12Unverified

Named so nobody mistakes them for checked facts. Every claim in this brief came from reading source; no build, test, clippy, or binary ran during recon or briefing.

  • The -p exit path dropping detached tokio tasks is a reading of main.rs:1954's shape, not a measurement — and it is the load-bearing assumption behind rejecting a plain detached writer. Test it before step 3 is coded.
  • The TUI's AgentEvent match may have a catch-all; if it does, a missing arm compiles and the title goes nowhere silently. Check first.
  • O_APPEND single-write atomicity for a <200-byte line is a POSIX assumption, already relied on at todo.rs:68.
  • --dump-config's exact output shape was not quoted from its body.
  • The test-count baselines were not re-run; the filing date is assumed.
  • The set of loop exit paths was counted by grep, not by reading the tool-execution region line by line.
  • A reasoning model returning thinking-content instead of text might yield no title. The failure mode is safe — no title, today's row — but it is unchecked.

13.1 What was signed off

All three open questions were settled before any code was written, and both mid-flight deviations were ratified at the second layer rather than absorbed silently.

  • D1 — the trigger. Block inline at the turn boundary, non-fatal on failure. Ratified, and its cost is stated at the site and in the commit: one round-trip between TurnEnd and tool dispatch, bounded to once per run by the latch.
  • D2 — the turn rule. Assistant turns from persisted state; an existing title short-circuits before the count, so --resume never re-titles.
  • D3 — VS Code deferred, at the stated cost that the two pickers disagree for a titled session.
  • The row shape — replacement, not prefix — ratified as the better reading of “semantic name > default id + first message”.
what was not verified

The drawn picker and the header glyphs need a TTY, so what was checked is the shared session_label builder — the exact string the picker consumes — and render_plain output, not the live overlay. Two wirings have no hermetic test: Status.title's local seeding and --title's apply site.
