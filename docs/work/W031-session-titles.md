## 1. The ask

Verbatim:

> rename session, session should support rename, and the rename using llm to rename
> session, the rename action auto trigger by the loop after n turns (default = 2),
> such that we can easily find session on resume (semantic name > default id + first
> message)

Three deliverables, in the human's priority order:

1. An explicit rename capability.
2. The name is **LLM-generated** and semantic.
3. The loop triggers it **automatically after N turns, default 2, configurable**.

The driver is the `/resume` picker. Its row today is `id · age · first user line`
(`crates/wcode-cli/src/main.rs:2411` `fn session_label(path: &Path) -> String`) and
`:2419` `let mut parts = vec![id.to_string()];` — the id half is an opaque
`{millis}_{uuid8}` key.

## 2. A bug found on the way

The "first user line" half is **not even reliable**.
`crates/wcode-harness/src/session.rs` `messages()` prepends `AgentMessage::summary(…)`
whenever a compaction boundary exists, and `summary()` is a `User` message
(`crates/wcode-harness/src/message.rs:73`). So `first_user_line`
(`crates/wcode-cli/src/main.rs:2454`) returns the constant string
`Summary of the earlier conversation (auto-generated by compaction):`
for **every compacted session** — i.e. exactly the long sessions a user most wants to
find. The same scan feeds the titler, so both must read persisted `Message` entries
and skip the synthetic summary.

Worth shipping on its own merit.

## 3. Scope

### In scope

- `SessionEntry::Title { id, title }` — appended, last-write-wins, read by
  `Session::title()`. Same shape as `Todo`/`ModelChange`/`EffortChange`.
- A bounded one-shot titler: first user message + first assistant text in, ≤ 60 chars
  out, sanitized.
- An automatic trigger at a turn boundary, gated on `title_after_turns` (default `2`,
  `0` = off).
- `Agent::set_title` / `Agent::title`, `Request::SetTitle`, `AgentEvent::SessionTitle`,
  plus the idle and mid-run-deferred actor arms.
- `/rename <text>` in the line REPL (`parse_command`) and the TUI (`COMMANDS`).
- `--title <text>` (distinct from `--name`, which is the A2A address,
  `crates/wcode-cli/src/main.rs:196`).
- `[session] title_after_turns` + `WCODE_TITLE_AFTER_TURNS` + a `--dump-config` line,
  loud on a bad value.
- The picker row prefers the title; the summary-prefix bug of §2 fixed by the same
  helper.
- The title surfaced in the TUI header segment (`ui.rs:825`) and the REPL `/sessions`
  listing (`repl.rs:1166`).

### Non-scope (explicit)

- **VS Code's picker** (`editors/vscode/src/sessions.ts:149`) — it reads only the first
  32 KiB (`readHead(path, 32 * 1024)`, `sessions.ts:104`), so a tail-appended `Title` is
  invisible for any long transcript. That is a head-reader-vs-tail-entry problem, not a
  label tweak; it gets its own work item. Consequence: the two pickers disagree for a
  titled session. Both rows identify the same session.
- **Re-titling on a schedule** — churn, drift, and it renames a session the user has
  learned to find.
- **Renaming the file or group dir.** Five parsers depend on the filename:
  chronological listing (`repl.rs:297`), `age_millis` (`main.rs:2430`),
  `GroupEntry::id` (`session_groups.rs:132`), the path handed to `--resume`,
  `session_id_of` (`tools/session_search.rs:465`). The title is **content**.
- **`session_search` reporting a title** — a different reader; a good follow-up.
- **The socket client's blank `· session` segment** (`main.rs:1064`
  `// The server owns the session id; the client cannot learn it yet.`) — a separate
  plumbing bug. The *local* path already sets it (`main.rs:1963`
  `session: agent.session_id(),`); only the remote client is blank.
- **A live refresh of the picker list.** `set_sessions` is seeded once at boot
  (`crates/wcode-tui/src/lib.rs:401`). The renamed row is stale until the next launch;
  the confirmation is immediate via the status line.

## 5. Decisions settled by the brief

### 5.1 The title lives as a `SessionEntry` (rejected: `meta.json` sidecar)

```rust
    /// The session's semantic name: last write wins, like `Todo`.
    Title { id: String, title: String },
```

Why the entry wins: one reader (`Session::open`), torn-final-line tolerance inherited
(`session.rs:127`), and released binaries skip it as `Unknown` (`session.rs:54`).
`Compaction` (`session.rs:38`) is the precedent for an LLM-produced string persisted as
an entry.

### 5.2 Derived from the first user message + first assistant text (rejected: the whole ctx)

Clamped to ~600 chars each ≈ 400 input tokens, ~15 output, **once per session**. The
whole `ctx` is rejected: unbounded cost, and the tail describes the *latest* work
rather than the session's purpose.

### 5.3 The trigger — **OPEN (D1)**

The "one writer" fear was wrong: a second writer already exists.
`crates/wcode-cli/src/tools/todo.rs:68`:

```rust
    /// The tool opens its OWN session handle (the agent's in-memory `Session` never
    /// sees this entry); both writers open O_APPEND and write one full JSON line
```

So the constraint is "one short O_APPEND write", not "the loop must write".

- **(a) Block inline**, like `compact_ctx` (`loop_.rs:177`). ~15 lines. Cost: one full
  request of dead time at turn 2 — the moment a user is most likely mid-typing.
  Mitigated by the W029 input queue, so keystrokes are not lost.
- **(b) Spawn, drain at the next boundary, settle at run end.** No stall. Cost: a
  second in-flight future plus a settle wrapper around **11** `return finish(…)` sites
  (`loop_.rs:124,141,433,444,460,475,705,709,725,731,737`).
- **(c) CLI-side policy, kernel untouched.** The CLI observes `AgentEvent::TurnEnd`,
  counts to N, and sends `Request::SetTitle`; the existing mid-run deferral
  (`actor.rs:652`) applies it at the run boundary. No settle wrapper, no in-flight
  future in the kernel. Needs its own request framing (`side_ask_with` hardcodes the
  `/btw` preamble, `agent.rs:484`).

Orchestrator's read: (a) is the smallest correct change; (c) may be strictly better
than both and deserves the reviewer's first pass. The brief itself recommends (b).

### 5.4 What counts as a turn — **assistant turns, from persisted state**

Count `AgentMessage::Assistant` in `ctx` at the boundary; title when the count satisfies
`title_after_turns` **and** no `Title` exists.

- The loop's own counter (`loop_.rs:143` `turns += 1`) resets every `run()`, so a plain
  chat never reaches 2.
- User submits means a long `-p` agentic run never titles.
- Assistant turns covers both, and being derived from persisted state it agrees across
  a resume. A compaction cannot inflate it (`summary()` is a `User` message).
- On `--resume`: an existing `Title` short-circuits **before** the count — no re-title,
  no counter restart. A pre-feature session titles itself at its first boundary: a
  deliberate one-request backfill.

### 5.5 Overwrite policy — set once; `/rename` wins and suppresses

The loop never overwrites an existing `Title`. `/rename` appends a new one, which by
definition also disables the auto-titler for that session.

### 5.6 Explicit rename surface

`/rename <text>` on both human surfaces + `--title <text>`, all through
`Request::SetTitle`. Over a socket `/rename` **works** — it is a `Request`, unlike
`/resume`, which is refused because it is a client-side directory listing
(`repl.rs:999`).

### 5.7 Surfaces — kernel + both human pickers; VS Code deferred

See the non-scope entry in §3. The 32 KiB head read is the reason, not laziness.

### 5.8 Config shape

```toml
[session]
title_after_turns = 2   # 0 = never auto-title
```

Per-knob `Option<usize>`, absent = kernel default, `TuiConfig::view`'s style
(`config.rs:501`). Range `0..=50`, loud at merge. `WCODE_TITLE_AFTER_TURNS` beats toml.
One `--dump-config` line.

### 9.1 The live check must use the configured model, not a local one

The titler is an **instruction-following** probe: its contract is "3–6 words, no quotes,
no trailing period, nothing else". A small local model is the instrument most likely to
fail that instruction — and it fails in a way that is indistinguishable from a bug in
`sanitize` or in the trigger. That makes the check both flaky and misleading, and a
flaky test is worse than none: it teaches the next person to ignore the result.

The live run therefore uses whatever `~/.config/wcode/config.toml` already resolves, with
**no `--base-url` and no `--model` flags**:

```sh
# confirm what will be used first — --dump-config redacts the key (main.rs:569 redact_key)
cargo run -p wcode-cli -- --dump-config | head -20

# then the two-turn run, on the real endpoint
cargo run -p wcode-cli -- --no-tui
```

Four consequences to state plainly:

- **It costs real tokens** — two turns plus one small title request, once per session. The
  design already bounds this (§5.2), and the title is never re-requested for a session that
  has one (§5.5), so the budget is small and non-recurring.
- **It exercises `sanitize` for real.** A competent model still returns quotes or a
  trailing period often enough that the sanitiser is genuinely tested — which is a
  *benefit* of the real endpoint over a local one, not a cost.
- **The refused-port case is different on purpose.** `http://127.0.0.1:9/v1` is an
  intentionally dead endpoint used to prove the error and retry paths; it never expects a
  successful completion. Keep it, and keep `WCODE_RETRY_MAX=2` on it.
- **A real two-turn `-p` run is the cheapest proof of the riskiest assumption.** It is the
  only way to show the title is settled *before* `process::exit` (§11.5) — the run must
  leave a `Title` line behind, not race the exit.

Unit tests never touch the network: they drive a scripted `StreamFn`, so `cargo test` stays
hermetic and free.

### 12.1 The census lesson — stop enumerating

Three censuses of the compile-break sites produced three different answers:

| Struct | Sketch said | Reviewer said | Actual (verified) |
|---|---|---|---|
| `AgentConfig` literals | 9 | 19 (list short by 7) | **19** |
| `Status` literals | 1 | 3 (list short by 4) | **7** |

The conclusion is procedural, not numerical: adding a **non-`Option`** field is a compile
error at every literal, so `cargo build` is the authoritative enumerator and the sketch
should not carry a list at all. The one case the compiler **cannot** catch is a `..spread`
literal — several exist in `ui.rs`/`lib.rs` — which must be found by hand.

### 12.2 Amendments that change the design

- **The auto-title is once per run, not once per boundary.** A per-run `title_tried` latch
  (`let mut title_tried = false;` before the outer loop). Per-run rather than persisted, so
  a resume retries once and §5.4's pre-feature backfill survives. Consequence: §5.3's
  "one full request of dead time at turn 2" becomes **one request per run, maximum** — which
  materially weakens the case against option (a) and strengthens D1 as locked.
- **The title call drops reasoning effort.** A title-local `let mut title_llm =
  cfg.llm.clone(); title_llm.effort = None;`, same model. Fixes the reasoning-model gap
  (§11.11) at the caller, so `title.rs` is unchanged. Thinking-text fallback is **rejected**:
  a thinking block's first line is planning prose, so it would store worse titles *and* hide
  the miss.
- **`Session::append_entry_at` is dropped.** It was `pub` with no caller; dead public API is
  a blocker in this repo. Gate withdrawn. Its consumer ("rename a session nobody has open")
  is not in §3 and gets its own item.
- **`COMPACTION_SUMMARY_PREFIX` moves to `message.rs`** as a `pub const` used by its own
  `format!`, re-exported by `title.rs`. Byte-identical output, no session-format change, and
  the correct single-source fix for §2's bug.
- **`session_label` stays private.** A private item is visible to descendant modules and
  `repl` is one, so `pub(crate)` was never required. `first_user_line` has exactly one
  caller, so the path wrapper is deleted in favour of `first_user_line_of(&Session)` plus a
  new `row_session(path)`.
- **A failed auto-title stays silent** — no `TitleSkipped` event. Against the
  `CompactionSkipped` precedent: that event exists because a compaction miss is expected,
  actionable and consequential. A title miss is cosmetic, at most once per run, leaves the
  session in its pre-W031 state, and offers the user nothing to do. Silence is pinned by a
  test asserting **no** `SessionTitle` and **no** `Error`.
- **The `AgentEvent` reconnect stays unfixed**, per `event.rs:243`'s own instruction. But
  §3's non-scope must record the real cost: the VS Code extension ships separately and
  spawns `wcode serve --stdio`, so an older extension against a newer binary drops and
  reconnects once per titled session, failing any in-flight `ask`.
- **Four incomplete `AgentEvent` matches**, not three: the TUI reducer, the REPL printer,
  `one_shot` (`main.rs:2496`, deliberately no arm) and `drive_workflow`
  (`main.rs:2832`, no arm). `run_command` is self-policing — it panics on a missing arm.

### 12.3 Gates added by the review

- `auto_title_failure_is_not_retried_at_the_next_boundary` — errors on every title call;
  assert **exactly one** title-shaped request across three boundaries. This is B3's teeth.
- `set_title_mid_run_is_deferred_and_still_reported` — asserts `Ask → Ack`, the `Tell`
  re-queue, **and** the `SessionTitle` arriving after the run.
- `rename_command_asks_the_backend`, `dump_config_names_title_after_turns`.
- `generate_refuses_an_empty_excerpt_without_a_call`, `excerpt_skips_a_compaction_summary`,

The REPL's title print arm cannot be pinned by a unit test: `print_events` writes straight
