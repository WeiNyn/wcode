# The wcode mark

One mark, two tiers. **Accepted** — [`D042`](../decisions/D042-wcode-mark.md). This
doc is the geometry and the rules; `D042` is the decision and its alternatives.

The mark is **`❯▌`**: the prompt and the cursor, the two glyphs the product is
made of. It is one ink, it reads at 16×16, and it is the only logo wcode has.

Everything below is generated by
[`docs/design/identity/gen.py`](identity/gen.py) — the reproducible source for
the px-tier SVGs. The files it writes:

| file | what it is |
|---|---|
| `editors/vscode/media/wcode.svg` | the activity-bar icon, 24×24, one ink |
| `editors/vscode/media/icon.svg` | the 128-unit tile field, `#3fb950` on `#0b0e13` |
| `editors/vscode/media/icon.png` | that tile at 256×256, for the marketplace |
| `favicon.svg`, `docs/book/favicon.svg` | the same ground (`#0b0e13`), `>_` still font-rendered |
| `docs/design/identity/candidate-a.svg`, `candidate-a-tile.svg` | the same two drawings, kept as the round-1 record |

## 1. Geometry

The viewBox is 24 units. Axis-aligned edges sit on a **1.5-unit grid**, so they
land on a whole pixel at 16, 32, 64 and 128 px (24/16 = 1.5, so a coordinate `c`
lands at `2c/3` px and a multiple of 1.5 is an integer). At 24 px, DPR 1, those
edges sit on a half pixel — soft, never wrong, and whole again at DPR 2.
Diagonals cannot snap to any raster and are on a 0.1-unit grid.

**The chevron** (the prompt). Centreline `(3.6,5) → (10.6,12) → (3.6,19)`, stroke
**2.5**, square-cut ends, sharp mitre at the apex: the outer point reaches
`x 12.37`, the inner one `x 8.83`. Arms at 45°, 7 units of half-height.

**The cursor.** An axis-aligned rect, `x 13.5 → 21`, `y 16.5 → 19.5`:
**7.5 × 3 units**, square corners (a terminal cursor cell has no radius), its
bottom at the chevron's baseline. On the 1.5 grid, so at 16 px it is exactly
**5 × 2 whole pixels**.

Both are filled paths, never strokes: some hosts force `svg { fill: … }` from
CSS, which would turn a `stroke=`-only icon into a blob. The shipped file is

```svg
<svg xmlns="http://www.w3.org/2000/svg" viewBox="0 0 24 24" fill="currentColor">
  <path d="M2.72,5.88 L8.83,12 L2.72,18.12 L4.48,19.88 L12.37,12 L4.48,4.12Z"/>
  <rect x="13.5" y="16.5" width="7.5" height="3"/>
</svg>
```

Artwork box 18.28 × 15.77, margins 2.72 / 3.00 / 4.12 / 4.12 — optically centred,
a hair left, which is right for a right-heavy composition.

## 2. One ink

`fill="currentColor"` on the root and **no hex anywhere in the file**. The
activity-bar icon is tinted by the host, so colour is not the mark's; and the
TUI's default theme is bare — `docs/tui-design.md` §1.3, "**`error` red is the
ONLY hue** … every other role is the grey ramp". The mark must therefore read in
solid grey and in solid white-on-dark, and it does: there is no counter, no hole,
no overlap and no second weight, so inversion changes nothing but the ink's
value.

## 3. The two tiers

**Px tier** — `editors/vscode/media/wcode.svg` (24×24, one ink) and the tile
(`icon.svg` / `icon.png`, 128-unit field shipping at 256). This is the tier with
a colour, and only the tile may have one (§5).

**Terminal tier** — the root surface's empty state, one `Block::Notice`, two
lines, both `dim` (a notice is dim end to end):

```
❯▌ wcode
❯ type a message · /help · F1 keys
```

Line 1 is the mark: `❯` and `▌`, both already in the glyph table. Line 2 is the
hint. They are one block joined by `\n`, so nothing is added to the transcript's
block kinds. The two rows share a leading `❯` by design: the first is the mark,
the second is the prompt it belongs to.

- **Root surface only.** A member surface's empty state is the hint line alone —
  the team surfaces are already the brand.
- **Zero new glyphs**, and §2 is byte-unchanged: `❯` is already the `user prompt`
  row, `▌` is already the live cursor and the selection bar.
- **Retired by the first block**, through the one function that already retires
  the hint (`clear_hint`, matching the constant), so there is no second retire
  path.

## 4. Measured

`rsvg-convert` at each real size, the file's `currentColor` resolved from a
host-supplied `color` (i.e. tinted from outside the file, as a host does), ink =
pixels above the half-coverage level, islands = 8-connected components of that
ink.

| mark | 16 px ink | islands | 24 px ink | 32 px ink |
|---|---|---|---|---|
| the previous `>_` | 8.6% | 2 | 10.6% | 9.6% |
| **`❯▌`** | **14.8%** | **2** | 14.9% | 12.9% |

The chevron and the cursor stay separate islands at 16 px — the gap holds. The
cursor is 2 px of solid ink at 16 px where the previous 2.2-unit underscore was
1.47 px of anti-aliased grey: **that** is what the mark fixes, and it is the
whole reason the drawing changed.

## 5. Colour

**Ink `#3fb950` on surface `#0b0e13`, contrast 7.61:1.** Both are borrowed, not
invented: `#3fb950` is the colour the mark has worn since the favicon
(`docs/book/favicon.svg`), and `#0b0e13` is the live site's own background
(`docs/book/style.css` `--bg`). The tile, the favicon and the book therefore
share one ground — the favicon's stray near-duplicate `#0d1117` is retired.

The TUI gets **no** colour from this. Colour lives only in the tile and the
favicon; the terminal tier is ink, because the bare default has no hue to spend
on a logo.

## 6. Rejected

- **B — the wordmark's `w`** (four bevelled strokes). The best drawing of the
  three at 64–128 px; rejected because the mark would duplicate the name it sits
  next to, and a letter cannot be typed into a banner beside itself.
- **C — the cursor cell** (a filled rounded square with the prompt knocked out).
  The best marketplace tile; rejected because at 16 px it is a blob among the
  activity bar's line icons — **48.4% ink, 3.3× the chosen mark** — and its
  terminal form needs a reversed cell, i.e. the highlight that already means
  *selection*.

Drawn block letters and reverse video are rejected in
[`D042`](../decisions/D042-wcode-mark.md) §Alternatives: the first needs a §2
amendment for three glyphs D023 removed, the second spends six rows on one
letterform *and* the product's only highlight.

## 7. Regenerating

```
python3 docs/design/identity/gen.py     # rewrites the px-tier SVGs + the sheet
rsvg-convert -w 256 -h 256 editors/vscode/media/icon.svg -o editors/vscode/media/icon.png
```

The script is deterministic: re-running it reproduces every SVG byte-for-byte.
It also prints the three artwork boxes it computed, so a geometry edit can be
checked against §1 without a renderer.
