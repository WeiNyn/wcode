wcode

A minimal, pi-like coding agent for the terminal — small, token-lean, and team-first.

Four Rust crates, ~52,000 lines: a ~10k-line kernel (wcode-harness — event loop, tool dispatch, hooks, JSONL sessions), a socket protocol (wcode-protocol), a full-screen TUI (wcode-tui), and a thin CLI (wcode-cli). One binary over any OpenAI-compatible endpoint.

Three ideas, taken seriously

  • 1Simple

    One small kernel (wcode-harness): an event loop, tool dispatch, hooks, JSONL sessions — and a thin CLI on top. Absent by design: MCP, a subagent framework, permission prompts, behavior config. Policy lives in code, via Hooks.

  • 2Token-minimal, built in

    Content-addressed read/edit — a line's 5-char anchor is its address, so old code is never re-typed. bash spills large output to a file and returns a bounded preview. Auto-compaction keeps the window lean, and an rtk hook can proxy shell output. Fewer tokens, less context drift.

  • 3Teams & workflows first

    Spawn named members, message them by name, and member them to peek at — or stop — a run mid-flight. A real task DAG with gates, dependency edges, and rework caps. Declare the whole team and workflow in [team] / [workflow]. Each member is its own surface in the TUI.

What's in the box

  • Full-screen TUI

    Three bands — transcript, input, status. Streaming markdown (CommonMark + GFM, syntax-highlighted), a 7-theme catalog with a Plain→Named→Indexed→Rgb color ladder, browse mode, drag-to-select, and a live team sidebar. It's a wcode-protocol client, so it drives a local or a socket session identically.

  • Sessions that persist

    Every conversation is a JSONL file: resume it, group a whole team's sessions together, and search across all of them with session_search. One-shot -p, an interactive line REPL, or the TUI — the same session.

  • Skills & instructions

    SKILL.md packages are discovered project-first; only each skill's name + description enter the prompt, and the body loads on demand. AGENTS.md / CLAUDE.md — a global file plus the ancestor chain — fold into the system prompt.

  • Plan mode

    Explore and propose without touching the workspace: the editing tools are disabled and mutating shell is refused, until you approve. /plan flips it live, even mid-run.

  • Extensible by code

    A tool is a TypedTool (typed args + a JSON schema). A policy is a Hooks impl — a reason from before_tool_call blocks the call and feeds it back to the model. A provider is a StreamFn. No config needed.

  • Any endpoint

    Speaks the OpenAI chat-completions wire, with a Responses-wire path. Retry/backoff on transient errors, a stream-stall timeout, and keyless local endpoints (Ollama, llama.cpp, vLLM) out of the box.

An orchestrator, delegating

$ wcode --agents --config .wcode/team.toml
# your team · explorer (read-only) · builder · reviewer

❯ implement the retry policy, then have it reviewed
⚙ message(explorer) → "map the retry seam"          ✓ done
⚙ task(create) #1 explore → #2 implement → #3 verify
⚙ message(builder)  → "#2 implement"                ● running
⚙ member(builder)   → "what are you on?"            ✓ 1 line
⚙ message(reviewer) → "#3 review the diff"          ○ queued

Install

  1. Homebrew

    brew tap WeiNyn/wcode https://github.com/WeiNyn/wcode
brew install wcode

  2. crates.io

    cargo install wcode-cli

  3. Prebuilt binaries

    Linux (x86_64, aarch64) and macOS (Intel, Apple Silicon) tarballs — with a sha256 — are attached to each release.

Quickstart

~/.config/wcode/config.toml:

model = "gpt-4.1"                          # required
base_url = "https://api.openai.com/v1"     # optional; any OpenAI-compatible endpoint
api_key = "sk-..."                         # optional
wcode -p "explain this repo"   # one-shot
wcode                          # start the TUI
wcode --agents                 # start with a team + workflow
