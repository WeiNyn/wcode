wcode

A coding agent for the terminal, built around teams and workflows — not a single agent that fires off opaque subagents.

Declare a team and a task DAG; the orchestrator delegates, and every member stays addressable and controllable live — peek at its work, ask it a question, or stop it, without waiting for it to finish.

Four Rust crates, ~52,000 lines: a ~10k-line kernel (wcode-harness), a socket protocol (wcode-protocol), a full-screen TUI (wcode-tui), and a thin CLI (wcode-cli). One binary over any OpenAI-compatible endpoint.

Teams and workflows, first-class

  • Declare the team

    [team] names your members at startup — or spawn one at runtime. Each gets its own model, role, tools, read_only, effort, and even its own provider. Address a member by name with message; peers lists the roster with live state.

  • Declare the workflow

    [workflow] is a real task DAG, not a to-do list: nodes with deps edges, gate nodes, and rework caps. A scheduler dispatches ready nodes, and a gate's reject re-opens the work it judges — so "review it" is an enforced edge, not a prompt.

  • Stay in control

    The member tool works mid-run: status peeks a member's last completed work, ask puts a question to it, and cancel stops it — all without waiting for its turn to end. The orchestrator never blocks on a worker.

A team, not a subagent

A typical agent spawns a subagent for a task and blocks until it returns one string — you can't see it, steer it, or stop it, and the plan is whatever the model improvised. wcode makes every worker a first-class member of a declared team.

A single agent is still one flag away — teams are opt-in (--agents).

What's in the box

  • Full-screen TUI

    Each member is its own surface, with a live sidebar (state + current action). Streaming markdown (CommonMark + GFM, syntax-highlighted), a 7-theme catalog, browse mode, and drag-to-select. A wcode-protocol client, so a local or socket session is driven identically.

  • Persistent sessions

    Every conversation is a JSONL file. A team's sessions persist as a group and resume together, and session_search reads across all of them. One-shot -p, a line REPL, or the TUI — the same session.

  • Token-minimal by design

    Content-addressed read/edit — a line's 5-char anchor is its address, so old code is never re-typed. bash spills large output to a file and returns a bounded preview. Auto-compaction keeps the window lean.

  • Skills & instructions

    SKILL.md packages are discovered project-first; only each skill's name + description enter the prompt, and the body loads on demand. AGENTS.md / CLAUDE.md — a global file plus the ancestor chain — fold into the system prompt.

  • Plan mode

    Explore and propose without touching the workspace: the editing tools are disabled and mutating shell is refused, until you approve. /plan flips it live, even mid-run.

  • Small, and extensible by code

    One kernel (wcode-harness) — no MCP, no permission prompts, no behavior config. A tool is a TypedTool, a policy is a Hooks impl, a provider is a StreamFn. Any OpenAI-compatible endpoint, keyless local included.

Install

  1. Homebrew

    brew tap WeiNyn/wcode https://github.com/WeiNyn/wcode
brew install wcode

  2. crates.io

    cargo install wcode-cli

  3. Prebuilt binaries

    Linux (x86_64, aarch64) and macOS (Intel, Apple Silicon) tarballs — with a sha256 — are attached to each release.

Quickstart

~/.config/wcode/config.toml:

model = "gpt-4.1"                          # required
base_url = "https://api.openai.com/v1"     # optional; any OpenAI-compatible endpoint
api_key = "sk-..."                         # optional
wcode -p "explain this repo"   # one-shot
wcode                          # start the TUI
wcode --agents                 # start with a team + workflow
